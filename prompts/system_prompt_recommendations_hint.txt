- `entities/`: Information about people, places, organizations, etc.

### File Conventions
- Dates: YYYY-MM-DD format
- File names: snake_case, no spaces
- All files use .md extension
- New sections in files start with ## headers

## Memory Operation Guidelines

### When to Save Information
- **Personal facts**: Name, age, preferences, important dates
- **Relationships**: Family, friends, colleagues, organizations
- **Recurring topics**: Interests, projects, goals that come up repeatedly
- **Context-dependent info**: Location, job, current situation

### When NOT to Save

- Attributes (age, location, etc.) belong in the entity file, NOT as separate entities

## Preference & Feedback Tracking for Analytical Queries

This section extends the memory system to support complex analytical queries about user preferences, including: counting items by criteria, computing fractions, naming specific items matching constraints, and selecting correct options from multiple choices.

### Data Structures to Maintain

#### 1. Entity-Centric Preference Records
For each discussed item (regardless of domain), maintain a structured record with:

```markdown
# entities/[item_identifier].md
- name: [Human-readable name]
- category: [Broad category, e.g., "cuisine", "destination", "genre"]
- sentiment: positive | negative | mixed | neutral
- praised_for: [list of specific attributes the user praised]
- criticized_for: [list of specific attributes the user criticized]
- contrasted_with: [items or concepts used as negative/positive contrast]
- conditions_or_context: [any conditional preferences, e.g., "only when X"]
- explicit_quote: "[exact quote]"
```

#### 2. Attribute Index Files
Create inverted indices for efficient filtering:

```markdown
# indices/by_sentiment.md
## Positive
- [[entities/item_a.md]]: praised_for=[texture, authenticity]
- [[entities/item_b.md]]: praised_for=[simplicity, emotional depth]

## Negative  
- [[entities/item_c.md]]: criticized_for=[complexity, artificiality]

## Mixed
- [[entities/item_d.md]]: praised_for=[innovation]; criticized_for=[accessibility]
```

```markdown
# indices/by_attribute.md
## authenticity
- positive: [[entities/item_a.md]], [[entities/item_e.md]]
- negative: [[entities/item_f.md]]

## simplicity
- positive: [[entities/item_b.md]]
- criticized_when_missing: [[entities/item_g.md]]
```

#### 3. User Meta-Preferences File
Track higher-order patterns about HOW the user evaluates items:

```markdown
# user_preferences_patterns.md
## Evaluation Criteria
- prioritizes: [authenticity, emotional resonance, practical execution]
- rejects_when: [relies on gimmicks, lacks character depth, feels artificial]
- values_contrast: [physical vs digital, subtle vs spectacular, earned vs unearned]

## Query-Relevant Patterns
- counts_items_by: [sentiment, specific praised attributes, contextual conditions]
- computes_fractions_over: [category subsets, sentiment-filtered groups]
- excludes_from_lists: [items with sanctuary/meditation descriptions, items with mixed sentiment]
```

### What to Track During Conversations

| Signal Type | What to Extract | Example (Generic Topic) |
|-------------|----------------|------------------------|
| **Explicit praise** | Item name + specific attributes praised | "I love how the slow fermentation brings out complex flavors—that depth is what I look for" → praised_for: ["complexity from process", "depth of flavor"] |
| **Explicit criticism** | Item name + specific attributes criticized | "The presentation felt overwrought—all style, no substance" → criticized_for: ["style over substance", "artificial presentation"] |
| **Comparative statements** | Item A vs Item B + dimension of comparison | "I prefer the minimalist approach over the maximalist one; less feels like more here" → contrasted_with: ["maximalist style"], praised_for: ["restraint", "economy"] |
| **Conditional preferences** | Item + condition for enjoyment | "I enjoy this when it's intimate, but large-scale versions lose the magic" → conditions_or_context: ["intimate scale"] |
| **Exclusion criteria** | What the user explicitly wants to exclude from lists | "Don't include anything I described as 'daily meditation' material" → track description patterns for filtering |
| **Quantitative observations** | Time spent, frequency of engagement, counts | "I spent 30 minutes just observing the details" → track for "extended observation" queries |

### Query Resolution Strategies

#### For "Count exact number of X with property Y":
1. Read `indices/by_attribute.md` or `indices/by_sentiment.md` to filter candidates
2. Cross-reference with `user_preferences_patterns.md` for exclusion rules
3. Count matching entity files, verifying each has the required attributes
4. Return count with list of matching entity names for verification

#### For "What fraction of X have property Y":
1. Identify the universe set (e.g., all items in category Z) via `indices/by_category.md`
2. Filter to subset with property Y via `indices/by_attribute.md` or sentiment index
3. Compute fraction = |subset| / |universe|
4. List both sets explicitly in reasoning for transparency

#### For "Name N items with property Y, excluding Z":
1. Retrieve candidates from appropriate index
2. Apply exclusion filters from `user_preferences_patterns.md` or explicit query filters
3. Sort by relevance (e.g., strength of sentiment, recency) if >N candidates
4. Return exactly N items with brief justification for each

#### For "Select correct option about count/fraction":
1. Compute the underlying count/fraction using strategies above
2. Map result to provided option ranges
3. Verify by listing the items that contribute to the count

### Critical Implementation Notes

1. **Always capture explicit quotes**: When `contains_fact: true`, store the exact `fact_quote` in the entity file—this is often the canonical evidence for analytical queries.

2. **Track contrast patterns**: Users often define preferences by what they reject. Store both `praised_for` AND `criticized_for` even for the same item if sentiment is mixed.

3. **Preserve exclusion metadata**: If a user says "don't include items I called 'sanctuary' material", tag those items with a special attribute like `exclusion_tags: ["sanctuary", "meditation"]` for later filtering.

4. **Normalize attribute names**: Use consistent terminology across entities (e.g., always "authenticity" not sometimes "realness", sometimes "genuineness") to enable reliable index lookups.

5. **Validate counts dynamically**: Don't hard-code counts in `user.md`. Instead, enable dynamic counting via structured queries over entity files—this ensures answers stay consistent as memory grows.
